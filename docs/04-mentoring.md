# 전달자·멘토링 운영

## 확정된 조건과 추가 질문

본인 노트북, 평일 5일 × 2시간, 코드 읽기 중심, Oracle·MySQL 비교, 지정 교재 없음입니다. 직접 작성하는 작은 예제는 디버거·로그로 확인합니다. 다음 질문은 확정된 조건 외의 내용을 구체화하기 위한 것입니다.

1. Oracle·MySQL 버전과 교육용 접속 환경은 무엇인가? 대표 업무와 프로시저의 길이·복잡도는 어느 정도인가?
2. 학습자는 SQL 외에 다른 언어를 써본 적이 있는가?
3. 교육 인원은 몇 명인가? 선택 자율 실습을 제공해도 되는가?
4. 교육 PC의 OS, 설치 권한, 인터넷·프록시 제한은 무엇인가? 별도 실습 DB와 익명화 데이터를 준비할 수 있는가?
5. 코드 읽기 평가에 사용할 실제 예제를 제공할 수 있는가? 후속으로 운영 전환을 계획하는가?
6. 실무 Java/Boot 버전과 JDBC/MyBatis/JPA 사용 여부는 무엇인가? 프로시저 호출을 유지하는 과도기 방식도 다룰 것인가?
7. 최종 실행 형태는 HTTP API, 배치, 스케줄러 중 무엇인가? 결과 동등성과 성능의 수용 기준은 누가 정하는가?

## 전달자의 준비

매 회차에 학습 목표 2~3개, 30줄 안팎 읽기 코드, 정상/경계/실패 입력, 예상 결과, 힌트와 해설을 준비합니다. 정답을 먼저 보여주기보다 입력·타입·분기·반환을 학습자가 표시하게 합니다. 예제는 같은 주문 업무를 점차 확장해 새로운 문법과 업무 맥락이 동시에 바뀌는 부담을 줄입니다.

실습 전 동일한 버전으로 리허설하고 필요한 다운로드·권한·DB 초기화를 확인합니다. 환경 문제와 개념 문제를 구별해 기록합니다. 디버깅할 때는 오류 메시지 첫 줄과 원인 예외, 문제가 난 코드 위치를 같이 읽습니다.

## 학습 기록 양식

```text
회차 / 날짜 / 학습자:
오늘 설명할 수 있게 된 개념:
읽은 코드와 입력:
실행 전 예상 / 실제 결과:
예상과 달랐던 이유:
오류 메시지 / 확인 순서 / 해결:
다음 회차에 다시 설명할 질문:
```

## 평가와 피드백

각 목표를 0(설명 불가), 1(힌트로 추적), 2(독립적으로 추적·근거 설명)로 기록합니다. 초급은 변수·분기·메서드 흐름, 중급은 객체·주입·SQL·예외, 고급은 트랜잭션·동시성·결과 동등성을 봅니다. 부족한 요소는 같은 업무의 더 작은 예제로 되돌아갑니다.

5일차 종료 후 학습자의 코드 읽기 설명과 비교 검증 결과를 전달자가 리뷰합니다. 실제 운영 전환은 별도의 업무 검증·배포 계획에서 결정합니다.
