# 프로시저 → Java 전환 학습 지도

전환의 기준은 문법이 아니라 업무 의미입니다. 입력·결과 집합·DB 변경·예외·트랜잭션·성능을 먼저 기록합니다. 집합 기반 SQL을 유지하고 Java에는 검증·분기·외부 연동·업무 흐름을 배치할 수 있습니다. 모든 프로시저를 반드시 Java 반복문으로 치환할 필요는 없습니다.

| Java 학습 요소 | 연결할 전환 요소 |
|---|---|
| 타입·메서드 | IN/OUT, NUMBER, 문자열, 날짜, 반환값 |
| 조건·반복 | IF/CASE, cursor, set 기반 처리 |
| 객체·컬렉션 | 행→DTO, 결과 집합→List, 복수 출력→결과 객체 |
| 예외 | 오류 코드·DB 예외→업무 예외와 원인 보존 |
| JDBC | 바인딩, 조회 건수, SQL 실행과 리소스 |
| 트랜잭션·동시성 | COMMIT/ROLLBACK, 락, 격리 수준, 재시도 |
| 테스트·성능 | 원본과 동일 입력 비교, 실패 주입, SQL 횟수 |

[요소별 비교와 예제](01-elements.md)를 학습한 뒤 [사례 양식](02-case-template.md)을 복사해 프로시저마다 별도 문서를 작성합니다. DB 방언이 정해지기 전 예시는 의사코드로만 사용합니다.
